# Computational Cell Reprogramming Review — Reproduction Materials

**Author:** Paola Vera-Licona (veralicona@uchc.edu)  
**Affiliation:** University of Connecticut School of Medicine, Farmington, CT, USA

Public reproduction package for the PLOS Computational Biology submission  
*Computational Cell Reprogramming: A Systematic Review of Cellular Intervention Design* (Vera-Licona Research Group, 2026).

This repository contains the scripts and data needed to regenerate the computational figures and Supporting Information S4 workbook that accompany the article. Supporting Information for the submission is **S1 to S4** (the bibliometric analysis is not part of this submission).

| Manuscript artifact | Folder | Output |
| --- | --- | --- |
| Main-text Figure 1 (assignment tree) | [`figure1/`](figure1/) | `Fig1_assignment.{pdf,png,tiff,eps}` |
| Main-text Figure 2 (settings and classes) | [`figure2/`](figure2/) | `Fig2_settings_classes.{pdf,png,tiff,eps}` |
| Supporting Information S3, Figure 1 (resource audit) | [`s3_figure1/`](s3_figure1/) | `S3_Fig1.{pdf,png,tiff,eps}` |
| Supporting Information S3 workbook | [`data/`](data/) | `SI_3_ReproducibilityAudit.xlsx` (input) |
| Supporting Information S4 (dataset reuse) | [`dataset_reuse/`](dataset_reuse/) | `SI_4_DatasetReuse.xlsx` |
| Frozen SI mirrors (S2–S4) | [`supporting_information/`](supporting_information/) | copies of the PLOS upload workbooks |

Supporting Information S1 (taxonomy PDF, including S1, Figure 1) accompanies the article as a PLOS Supporting Information file. It is not regenerated by the Docker workflow above.

## Quick start (Docker — recommended)

Requires [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine + Compose plugin).

```bash
# Build the image once
docker compose build

# Regenerate Figures 1 and 2, S3 Figure 1, and SI_4 (offline, ~1–2 minutes)
docker compose run --rm run-offline

# JupyterLab with guided notebooks
docker compose up jupyter
# Open http://localhost:8888 and open notebooks/00_Run_All_Offline.ipynb
```

Outputs are written into this repository folder (mounted as a volume), so they persist after the container exits.

## Quick start (Jupyter notebooks)

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-all.txt
jupyter lab notebooks/
```

| Notebook | What it runs |
| --- | --- |
| [`notebooks/00_Run_All_Offline.ipynb`](notebooks/00_Run_All_Offline.ipynb) | Figure 1 → Figure 2 → S3 Figure 1 → SI_4 |
| [`notebooks/01_Figure1_Assignment.ipynb`](notebooks/01_Figure1_Assignment.ipynb) | Figure 1 only |
| [`notebooks/02_Figure2_SettingsClasses.ipynb`](notebooks/02_Figure2_SettingsClasses.ipynb) | Figure 2 only |
| [`notebooks/03_S3_Figure1_ResourceAudit.ipynb`](notebooks/03_S3_Figure1_ResourceAudit.ipynb) | S3 Figure 1 only |
| [`notebooks/04_DatasetReuse_Table.ipynb`](notebooks/04_DatasetReuse_Table.ipynb) | SI_4 xlsx only |

Notebooks call the same Python scripts as the command-line workflow — they are thin wrappers, not duplicate logic.

## Quick start (command line)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
bash scripts/run_offline.sh
```

### Individual scripts

**Figure 1**

```bash
cd figure1 && python fig1_assignment.py
```

**Figure 2**

```bash
cd figure2 && python preview_rows.py
```

Reference numbers on Figure 2 are frozen in `figure2/citekey_to_ref_num.json` (PLOS citeproc order from the compiled manuscript).

**Supporting Information S3, Figure 1**

```bash
python s3_figure1/render_s3_fig1.py
```

Reads `data/audit_source.csv` (aligned with `data/SI_3_ReproducibilityAudit.xlsx`). Trip-wire asserts verify headline Section 5 counts for the 59 single-class methods (45 with code; 26 at 4 of 4 among those bars; 15 of 45 with FAIR4RS-based score ≥ 3).

**Supporting Information S4**

```bash
cd dataset_reuse && python build_si_4_xlsx.py
```
